# HLC wide UNet: v and score prediction

New experiment, run `hlc-wide-vscore-20260927-v1`. Historical trainers, weights,
configurations, and results are unchanged. The user requested two concurrent
trainers, each on its own H200. On2026-09-27 the user confirmed one complete
epoch per model:2,608,772 records,40,763 updates, final batch4. This explicitly
overrides the default five-epoch formal budget for this comparison only.
See `vscore_plan.json` for the frozen run budget.

## Shared controls

- HLS-LST-CrossSensor, `processed_data/v1`, full training membership 2,608,772

- The existing full-train normalization and fixed independent 512 validation
  members are reused. No test evaluation or test selection.
- UNet 64/128/256/512/1024, 259,049,729 trainable parameters; frozen Prithvi
  1024-dimensional features and original attention blocks.
- Fresh orthogonal initialization with seed 20260927. UNet and encoder hashes
  must match across variants. Same epoch members/order, augmentation, and
  separate identically seeded diffusion RNG. Micro/effective batch64, no

- Adam lr2e-5, warmup5000 updates, cosine to1e-6, gradient norm clipping1,
  EMA copying live weights until update5000, then decay0.9999.
- Every epoch visits all records once; 40,763 updates, last batch4. No dropped
  or padded tail. Technical smoke uses132 records and deliberately tests tail4.

## Objective and schedule

Both use VP Gaussian corruption x_t=a*x0+sigma*epsilon, a^2+sigma^2=1.
There are1000 beta values linearly spaced1e-6..0.01; training samples uniformly
from noisy discrete states1..1000. The clean state is not a training target time.
The original SR3 model sampled continuously inside schedule intervals; this
experiment explicitly uses discrete states for both new variants.

- v: direct network prediction of a*epsilon-sigma*x0; masked MSE.
- score: direct raw score output; variance-weighted DSM computed stably as
  mean((sigma*score+epsilon)^2). No hidden epsilon-output wrapper.

Loss is averaged over valid pixels per record, then equally over records.
Score DSM has an equivalent epsilon-error expression; this is a parameterization
comparison, not evidence for fundamentally independent generative theories.
Loss magnitudes are not cross-variant quality metrics.

## Selection, sampling, and measurements

Validate at the nearest following batch boundaries to25/50/75/100 percent of
each epoch, on the same512 records with fixed noise. Choose best EMA by50-NFE
RMSE; preserve final EMA separately. Both checkpoints get the same50/20/10/5-NFE
deterministic DDIM sweep. The grid includes noisiest and least-noisy training
states, followed by the clean endpoint. x0 is clipped to[-1,1], then epsilon is
recomputed consistently. This differs from the historical DDIM clipping behavior;
historical epsilon L1/ResShift metrics are contextual references, not controlled
baselines for this comparison.

Inference starts with Gaussian noise, as in the historical schedule. Terminal
SNR is small but nonzero; fewer-step conclusions apply to this fixed schedule,
not all possible zero-terminal-SNR designs.

Record valid-pixel Celsius RMSE/MAE, actual NFE, inference time including one HLS
encoding per sampling call, post-first-batch median latency, sampled training
data-wait/update latency, and GPU memory. Identical16 validation example members
are saved for every sampler budget. Evaluation RNG does not alter training RNG.

## Lifecycle

`vscore_modal.py` permits at most two H200 containers, one per model chain.
Each bounded segment saves optimizer, live model, EMA, and CPU/CUDA RNG state
and queues its own continuation. Each model stops at the confirmed exact budget.
Duplicate launches are guarded. A technical smoke checks batch64, finite loss
and gradients, checkpoint/reload, tail4, and sampling for both targets before
formal launch. No user-facing result may call the132-record smoke a full epoch.

`vscore_control.py status` is read-only; `download` also fetches completed
metrics and example arrays. `smoke` and `start` explicitly submit jobs. Always
use Modal profile `runlongyu-target`, environment `main`.
